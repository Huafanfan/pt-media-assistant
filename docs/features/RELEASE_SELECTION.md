# Feature：候选片源理解与推荐

编号：RELEASE-001。日期：2026-09-19。状态：**待用户审阅，未批准实施**。

执行清单：[RELEASE_SELECTION_TODO.md](RELEASE_SELECTION_TODO.md)。本文为拟议验收合同；本轮只交付文档，不包含实现、付费模型调用、真实下载或部署。

## 1. 背景与用户结果

用户使用极空间 NAS 自带的播放 App 和电影墙；本项目无需增加播放、刮削或媒体服务器。当前最主要的问题是：作品显示“有资源”，但候选标题难懂、版本差异不清楚，不知道应该下载哪个。

目标：用户不必理解英文发布名，就能看清候选包含什么、是否符合观看范围、推荐理由和仍未确认的信息，然后明确选择一个片源进入现有下载确认流程。

电影解决“哪个版本适合我”；电视剧和综艺首先解决“包含哪季、哪些集或期、什么节目版本，有没有缺漏或重叠”，再比较规格。

## 2. 当前基础与本次范围

当前工作区已具备作品详情、Prowlarr 候选快照、片源筛选、下载预检及确认；`ReleaseSummary.season` 明确是标题推断。现有 AI 模块中已有资源排序职责，应检查并复用，不另建相互冲突的排序体系。当前工作区有未提交修改，实施前必须重新核对基线。

### 本次包含

- 所有候选入口使用一致的结构化展示与排序语义，包括作品详情、AI 推荐打开的详情、片源直搜。
- 电影、电视剧、综艺的观看范围模型；同范围分组比较。
- 可解释、确定性的服务端推荐，最多三项不同取舍，不强行凑数。
- 按需 AI 辅助解析复杂标题、解释版本差异、转换自然语言偏好。
- 缺失、冲突、过期、范围未知等状态与降级流程。
- 对当前候选快照的覆盖和重叠分析；完整性证据不足时不做确定结论。

### 本次不包含

- 播放、刮削、文件整理、Jellyfin、Radarr/Sonarr 部署。
- 自动下载、订阅追更、后台找资源、批量提交、修改 qB 队列或文件。
- NAS 片库同步、历史下载去重、自动识别用户已拥有的集数。
- 新增第三方元数据服务或自动获取种子文件来核验清单。完整性缺乏证据时保留未知。
- 将完整剧集拼成自动购买式下载方案。本次只显示候选间的补齐线索，逐个手动确认。

## 3. 主要概念与证据

| 概念 | 定义与限制 |
| --- | --- |
| 观看目标 | 作品、类型、季或年份、集/期/日期范围、节目版本；由用户选择或确认 |
| 候选覆盖 | 发布资料声称或可靠清单证明的范围，不等于已经下载或片库已有 |
| 标题标注 | 从标题提取的字段，卡片显示“标题标注”；AI 解析仍属于此类证据 |
| 已核验 | 可追溯的结构化来源或可靠文件清单支持该项结论；不是模型自报置信度 |
| 完整性未知 | 总集数、候选覆盖或对应关系不可靠，不能宣称全集、缺集或补齐 |
| 节目版本 | 正片、加更、纯享、会员版、预告、花絮等；未知保留，不合并成正片 |
| 当前可推荐 | 目标匹配、硬条件满足且达到证据门槛；不承诺下载速度、画质或设备兼容性 |

证据必须逐字段保存：值、来源种类、最小原文片段或字段名、解析器版本；冲突保留双方证据。AI 不得把推断提升为已核验。一个资源标题明确写 S02E01–E08，可以显示“标题标注第 2 季 1–8 集”，不能因此说已核验全部文件。

“全集/Complete”只是发布者声明。宣称“完整第 2 季”需要可信的预期集集合和候选覆盖证据；“12 个文件”不等于“12 集正片”。用户输入目标 E01–E12 定义的是请求范围，不证明官方共 12 集。

## 4. 用户流程与界面

### 4.1 电影

打开片源 → 默认均衡排序 → 查看最多三张推荐卡 → 展开全部版本 → 选择 → 原有预检 → 明确确认下载。

推荐卡按实际候选提供“均衡首选”“更重画质规格”“节省空间”等不同取舍。相同候选只出现一次，缺少合适替代就少显示。没有可靠画质比较证据时，不称“画质最好”。

### 4.2 电视剧

先显示季选择和目标范围：整季、指定集数、浏览全部。候选标题提取的季选项注明“来自片源标题”，不冒充完整剧集目录；允许用户输入目标季/集。作品信息已明确指向某季可预选并显示依据；多季含糊时不跨季推荐。

选择目标后分组：覆盖目标范围、部分覆盖、单集、范围待确认。范围确认级别始终可见。浏览全部时按季和范围展示，不给跨季综合首选。

示例：用户目标第 2 季 E01–E12，候选 A 标注 E01–E12、B 标注 E01–E08、C 标注 E09。A 显示“标题标注覆盖目标，文件范围未核验”；B 显示“按标题范围，目标中 E09–E12 未覆盖”；C 在第 9 集组。不同组不混算体积和画质优劣。

连载中不得将“更新至 E08”称为全集。没有可信总集数时不显示确定的全季缺集数量。多季合集明确列出涉及的季，不能当作单季等价版本；超出目标的范围提示额外下载内容。

### 4.3 综艺

在季/年份之后选择期数或播出日期，并明确正片/加更/纯享等节目版本；无法确认属于综艺时允许用户切换当前目标类型，不修改上游作品分类。

- 按日期和按期数是不同编号空间；没有映射证据不能互换。
- 上/下集、上/下期保留分段信息；第 8 期上不等于完整第 8 期。
- 加更、纯享与正片分别分组；正片目标下不推荐纯享作为等价替代。
- “2026”可能是节目年份也可能是日期的一部分，不强制解释为季编号。
- 混合合集展示包含的已知版本，未知部分提示，不能仅靠文件数判断完整。

### 4.4 卡片层级

1. 首行：作品/季集期范围与节目版本；电影显示版本差别。
2. 核心规格：分辨率、片源类型、编码、动态范围、总体积。
3. 下载条件：免费状态、做种人数及快照时间；未知与否定分开显示。
4. 一句推荐理由和关键注意事项；支持查看规则依据。
5. 字幕/音轨仅展示可追溯信息；没有证据显示未知。NAS 播放兼容性不预设。
6. 原始发布名、来源标签和证据折叠显示，可展开核对。

合集体积明确为总量。每集平均体积只在正片集数可靠、范围可比时显示，并注明估算；不得用整个合集与单集直接比较“小体积”。不展示看似精确但无法解释的 AI 百分制评分。

### 4.5 偏好与交互

提供“均衡优先 / 画质规格优先 / 小体积优先”互斥排序预设；“只看免费”为独立硬过滤，可与预设组合。字幕、音轨、体积上限等设置区分必须与优先。

自然语言示例：“第 2 季整季，20GB 以内，最好中文字幕。”AI 转换为可见的条件草稿，用户应用后重排；“最好”是软偏好，“必须”是硬条件。含糊的“20GB以内”在整季目标下默认指单个候选总量并明确显示，不解释为每集额度。冲突条件提示，不静默放宽。

偏好本次按当前页面/会话生效，可继承现有可兼容偏好，但不新增家庭长期设置或自动覆盖已有偏好。切换作品重置观看范围；切换排序和过滤保留合理目标，回到第一页。排序更新不自动替用户更换已选资源。

移动端先展示范围控件和简短卡片，详情可展开；键盘可操作，状态不只靠颜色，长标题不挤压选择按钮。确认面板重复展示实际选中的季集范围及不确定项。

## 5. 排序与覆盖计算合同

排序在服务端统一实现，输入为目标、规范化偏好和同一有效快照。AI 不直接决定最终 release ID 或修改事实字段。

处理次序：

1. 验证作品匹配，排除明确错误作品；身份含糊者进入待确认。
2. 应用硬条件：范围/节目版本、体积、免费、指定语言等；未知不算满足。范围允许标题证据的浏览推荐，但必须带标题标注；用户要求“核验完整”时未知不可通过。
3. 在相同目标下计算覆盖、额外内容和候选间重叠，按覆盖类型与证据级别分组。
4. 在同组内根据预设排序；已知有做种者的可推荐候选优先，零做种或未知进入可展开的可用性待确认区。
5. 用确定性理由码生成解释，最后以稳定键打破平局，保证相同输入结果一致。

均衡预设：优先满足软偏好、范围无额外负担、规格信息可靠；在相同分辨率/来源档位内优先较小体积，再比较做种数。规格优先：依据明确分辨率和来源档位排序，但不把 HDR、编码或码率单独当作绝对画质分。小体积优先：在同范围且硬条件满足的候选内按总字节数升序，未知体积靠后。具体来源档位表在实现前作为常量及 fixture 固定，未知不强行定级。

“只看免费”只接受上游明确且仍在已知有效期内的免费状态；未知、非免费、已过期均不符合。最终提交仍执行现有预检；无法获取实时优惠时不得承诺下载期间一直免费。

覆盖运算以结构化单元集合/区间为基础，单元包含季、集或期/日期、分段和版本。不同季、编号空间或版本不能直接求交；冲突标记待确认。必须限制展开数量，异常大范围不得导致资源耗尽。

补齐线索只针对当前目标和当前快照，例如“A 与 B 按标题互补，仍未核验”；不声称用户缺这些集。没有可靠目标全集合时不输出“已补齐”。不提供批量加入下载操作。

所有“推荐”限定于本次已获取候选，不声称全站最优。继续使用现有候选上限（当前最多 50 条）；先对完整快照计算，再分页展示，不能只排当前页。

## 6. AI 合同、成本与降级

### 调用方式

- 打开页面立即显示规则结果，不等待或自动触发付费 AI。
- 用户点击“AI 帮我比较”或提交自然语言偏好时调用，复用当前配置的 provider，不引入新模型依赖。
- 每次动作最多一次请求，不自动修复重试；超时 20 秒，失败返回规则解释。
- 每次最多发送 12 个与目标最相关候选、每个标题最多 300 字；输出上限 1500 tokens。超过上限明确“AI 已分析 X/N 项”，不能把子集分析称为全量。
- 单会话最多一个在途请求、每分钟最多三次，服务端总并发最多二，超限明确提示；参数可配置。
- 同快照、目标、偏好、解析器/提示词版本的结果在有效期内缓存；分页不调用模型，修改条件不自动付费重试。

### 输出与验证

AI 只能返回候选字段解析建议、受限理由码及证据引用、偏好草稿。ID 必须属于本次白名单，输出经过严格 schema 校验，文字按纯文本渲染。

对解析建议验证原文证据与允许的转换规则；无证据的字幕、音轨、全集判断拒绝使用。不能用未经验证的自由文本推荐理由绕过校验。无法验证的推断只进入待确认，不参与硬条件通过或自动获得首选。

AI 结果到达后由服务端重新计算合法排序；保留当前选择，标记建议已更新。新目标或新快照产生后丢弃旧响应；取消/离开停止后续处理，不承诺已发请求未计费。

### 数据边界

仅发送必要标题摘要、规格、大小、做种状态、优惠状态和当前目标；站点用无地址标签。禁止发送 Cookie、passkey、API key、GUID、下载 URL、tracker、NAS 路径及全量任务历史。页面在首次使用附近说明将发送精简片源信息到已配置 AI 服务。

资源标题是数据，其中指令不能执行。模型没有下载、刷新索引器、任意 URL 或文件工具。日志仅包含计数、耗时、错误类别和 usage，不记录原始片源或提示词正文。

## 7. 拟议技术结构

以下是实施方向，具体文件落点需按当时工作区核对，不重写已有无关功能。

| 模块 | 职责 |
| --- | --- |
| `src/shared/` 新增片源选择合约 | `SelectionTarget`、`FieldEvidence`、`ReleaseCoverage`、`SelectionPreferences`、`RankedRelease`、错误/状态枚举 |
| 服务端片源解析模块 | 确定性字段提取、冲突检测、证据保留，与现有 parser/Prowlarr 字段衔接 |
| 服务端选择服务 | 快照校验、覆盖分组、纯函数排序、推荐理由、分页前全量计算 |
| `src/server/ai/` 适配 | 复用 provider，按需有限输入、schema 验证、缓存、取消与限流 |
| 客户端共享候选组件 | 范围选择、推荐卡、分组列表、证据展开；详情与直搜共用 |
| 现有下载预检/确认 | 保持不透明 release ID 和现有校验，补充范围及不确定性展示 |

关键合约：

- `SelectionTarget`：作品引用、movie/series/variety/unknown、季/年份、episodes/issues/dates、segments、edition、browse/whole/explicit 模式。
- `ReleaseCoverage`：kind、范围、版本、evidence、conflicts、completeness（verified/claimed/unknown）；“claimed”不等同“verified”。
- `RankedRelease`：releaseId、group、rank、reasonCodes、warnings、constraintResults、推荐角色。
- 排序结果绑定 snapshotId、targetRevision、preferencesRevision、algorithmVersion 和 checkedAt。

拟议接口：`POST /api/releases/selection` 只对已有快照做规则计算；`POST /api/releases/selection/assist` 按需 AI。请求仅接受快照引用、目标、偏好及有限自然语言，不能由客户端提交上游事实或任意 URL。沿用会话/来源校验；AI 额外限流和取消。路由名可调整但语义不变。

片源直搜若尚无可引用快照，需要补服务端受限快照引用；没有已确认作品时只提供字段整理、分组和“待确认”提示，不将字符串相似视为作品匹配已核验。

快照过期明确返回过期状态，让用户主动刷新；不自动重新查询 Prowlarr。规则重排、分页、AI 比较不应额外查询索引器。释放/刷新快照时同步失效结果缓存，避免旧 ID 下载。

## 8. 错误与空状态

| 场景 | 界面结果 |
| --- | --- |
| 有种子但目标不匹配 | “找到候选，但没有符合当前季/集范围的版本”，可查看其他组 |
| 硬条件过滤为空 | 显示具体条件和不满足原因，由用户修改，不自动放宽 |
| 范围/字幕未知 | 明确未知，保留待确认候选，不补造字段 |
| AI 未启用/超时/限流/无效输出 | 规则结果持续可用，提示 AI 未完成 |
| Prowlarr 查询失败 | 与“没有资源”区分，保留适当的旧快照时间提示 |
| 全部无做种或未知 | 不给普通首选，显示可用性待确认，不等同绝对无法下载 |
| 目标变更/旧请求晚返回 | 只接受当前 revision，不覆盖新页面状态 |
| 快照过期 | 保留可读摘要但停止使用过期选择，提供主动刷新入口 |

## 9. 验收标准

以下为实施后的验收要求，当前均未执行：

1. 硬条件违规推荐为零；未知字段不能当作满足。
2. 电影、剧集、综艺三个入口场景都能完成选择到 mock 下载确认，只有明确确认才提交一次。
3. 同一快照在详情、AI 入口和直搜使用一致事实/排序规则；作品未确认的直搜保持待确认语义。
4. 标题“全集”、单集、合集、跨季、综艺正片/加更/纯享、日期/期数、上下期均有独立 fixture。
5. AI 不可用时仍可筛选、排序、展开证据并选择；规则结果无需付费请求。
6. 重新排序不查询 Prowlarr、不更换已选资源；旧异步响应不覆盖新目标。
7. 桌面和手机均能看清范围、总体积、推荐原因和未知项，键盘可操作。
8. 至少 12 组人工审阅样例覆盖三类内容，逐项检查首选或不推荐的原因；合理推荐不少于 10 组，涉及范围/版本/硬条件的严重错误必须为零。
9. 定向测试、类型检查、全量测试、生产构建及浏览器 mock 验证通过；真实下载不作为验收手段。付费模型 smoke 和上线另行明确授权。

## 10. 审阅默认方案与后续边界

建议按本文批准整项功能，实施顺序为合约与解析 → 规则排序 → 统一 UI → 按需 AI → 综合验证。第一版不要求接入新季集元数据源；信息不足明确未知，因此不承诺所有剧/综艺都能自动判定完整。

可靠文件清单核验、外部季集目录、长期偏好、片库去重、自动补集以后单独立项。本文件审阅通过不自动授权服务器部署或真实下载。
